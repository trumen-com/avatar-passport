# ADR 001: Model choice

- **Status:** Provisional until the Phase 1 gate. The final model per job is picked after Phase 2 evaluation on our local test set.
- **Date:** 2026-10-10
- **Evidence:** `docs/research/model_candidates.md`, which has the links, licences, classes, sizes and sources.

## Context

- **Jobs.** The pipeline (CLAUDE.md section 4) needs damage segmentation, car-part segmentation, plate and face detection for blurring, a generic car/person detector, and VIN OCR.
- **Constraints.**
  - CLAUDE.md section 3 asks for pretrained damage models with no training, and prefers self-hosted parts models.
  - The deploy runs on CPU with ONNX.
  - Every licence must be flagged (section 2).
  - The deadline is 2026-10-11 13:00, so training is a fallback only.
- **Licence situation.**
  - Every Ultralytics checkpoint we use carries an AGPL-3.0 stamp, and the user has chosen AGPL-3.0 for the repo.
  - The best damage weights were trained on CarDD, which is non-commercial.

## Decision

All of the following models run in the Phase 1 smoke test.

| job | model(s) | why |
|---|---|---|
| damage | 1. mitbersh/car-damage-segmentation (YOLO26m-seg, 896); 2. Danishali273/Car-Damage-Type-Segmentation (YOLO26l-seg, 640); 3. harpreetsahota/car-dd-segmentation-yolov11 (YOLO11x-seg, 1024 per its card; the checkpoint was trained at 1280) | mitbersh is the best documented. It ships an inference config with damage-to-part matching, and its author also made the parts model below. Danishali is a second YOLO26 opinion. harpreetsahota is YOLO11, so it still works if YOLO26 checkpoints fail to load. |
| parts | mitbersh/car-parts-segmentation (YOLO26s-seg, 768) | Pretrained, with no API key and no training. Its 33 side-aware classes include fender, quarter-panel, rocker-panel, roof and license-plate, none of which carparts-seg has. Training data is CC0. |
| plate | morsetechlab/yolov11-license-plate-detection v1n (.pt on GPU, .onnx on CPU) | Small (5.5 MB .pt). A third party reports testing it on Uzbek plates ([IzzatulloOne/plate-recognition-uz](https://github.com/IzzatulloOne/plate-recognition-uz)). |
| face | OpenCV Zoo YuNet `2026may` (OpenCV 5) / `2023mar` (OpenCV 4.x, Colab) | Tiny (0.23 MB), runs through OpenCV `FaceDetectorYN`, and the model licence is MIT. |
| car / person | Ultralytics YOLO26n (COCO) | Same stack, 5.5 MB. |
| VIN OCR | RapidOCR 3.10.0, with EasyOCR 1.7.2 as a comparison | The same ONNX CPU path on Colab and on the deploy. EasyOCR is compared because it has a character allowlist. |

**What the smoke test must show (gate)**
1. Every model loads with ultralytics 8.4.175 on the RTX 5050 (CUDA, sm_120) and on the CPU, and its runtime `model.names` is recorded. YOLO26 needs at least 8.4.0.
2. The annotated outputs on our own video frames and photos look sensible to the user.
3. The damage-on-part preview puts damage on the right panels.
4. Plates and faces are blurred before any image is written. Spot-check the copies in `data/processed/`.
5. The VIN is read correctly by RapidOCR or EasyOCR, or the failure is understood and written down.
6. Latency per model and runtime is generated by scripts into the marker blocks, never typed. This includes ONNX Runtime CPU pinned to 2 threads, labelled as the proxy for HF CPU Basic.
7. ONNX export works for every model we keep, since Phase 4 runs ONNX on CPU.
8. Optional: check whether the parts model's `license-plate` masks agree with the plate detector. If they do, they can be a second signal for blurring.

**Rule after the gate (provisional)**
- **Pick:** per job, keep the smallest model whose outputs look right and whose 2-thread proxy latency fits the brief's **target** of about 10 to 20 s per inspection. That figure is a target from CLAUDE.md section 1, not a result.
- **Final choice:** made only after the Phase 2 numbers (mask mAP50, part-level recall, false positives per car, by slice).

### Deviations from CLAUDE.md

1. **RapidOCR instead of PaddleOCR.** Section 3 asks for "PaddleOCR vs EasyOCR".
   - PaddleOCR needs the paddlepaddle wheel (194.8 MB, plus paddlex). RapidOCR bundles PP-OCRv6 small models as ONNX in a 27.3 MB wheel and runs on onnxruntime. Both sizes are reported from PyPI (`phase0_findings_vin.md` section 1).
   - EasyOCR still runs, as the comparison.
2. **SAM 3 dropped** as the plate fallback. It is gated behind manual approval, `sam3.pt` is 3.45 GB, and [Ultralytics reports](https://docs.ultralytics.com/models/sam-3/) 2,921 ms per image on an RTX PRO 6000 GPU (reported, `phase0_findings_models.md` section 3). Section 3 already says to avoid it on a CPU deploy.
3. **A pretrained parts model instead of Roboflow or training.**
   - The mitbersh parts model needs no Roboflow API key or paid credits and no training time.
   - Training YOLO26n/s-seg on `carparts-seg.yaml` stays the fallback. It must use `fliplr=0.0`, because Ultralytics' horizontal flip does not swap the left/right class ids.
4. **Deterministic utilities in `src/` before Phase 3.**
   - `vin`, `io`, `frames`, `quality`, `privacy`, `timing` and `synthetic` are written now, and the notebook imports them. This saves a port later.
   - ML inference wrappers stay in the notebook until the gate.
5. **Supporting modules outside the section-6 tree.**
   - Python modules: `src/avtopassport/{io,paths,timing,synthetic}.py` and `src/avtopassport/vin/checkdigit.py`.
   - Scripts: `scripts/render_results.py` (writes measured tables into marker blocks), `scripts/bench_cpu.py` (CPU latency in its own process), `scripts/build_notebook_01.py` (generates the smoke-test notebook) and `scripts/build_repair_prices.py` (builds `data/reference/repair_prices.csv`).
   - Config: `pyproject.toml` and the `requirements-dev.txt`, `requirements-colab.txt` and `requirements-exclude.txt` files.
6. **The notebook runs locally on the RTX 5050 and the CPU.** Section 3 asks for Colab GPU and CPU runtimes. The Colab run is the user's step.
7. **The deploy CPU latency is a local proxy.**
   - It is measured with ONNX Runtime pinned to 2 threads on the laptop and labelled "proxy for HF CPU Basic (2 vCPU)".
   - This holds until Phase 4 measures it on the real host, as section 8 requires ("full inspection time measured on deploy hardware").

## Consequences

- **AGPL-3.0.** The repo must stay AGPL-3.0, and the deployed app must link to its source (ADR 003).
- **Damage weights are demo/research only, and the pitch must say so.** A commercial pilot needs two things:
  - a damage model retrained on licensed data, such as the dealer's own body-shop photos or the CC0 Humans in the Loop damage images;
  - either an Ultralytics Enterprise licence or a non-AGPL stack.
- **Quality is unknown until Phase 2.** The smoke test proves loading, plausibility and speed, not accuracy.
- **Weights are not committed.** `scripts/download_models.py` pins each source revision, size and SHA-256.
- **Fallback if a heavy model is too slow at 2 threads** (the YOLO11x-seg at 1024 is the most likely): drop it rather than buy faster hardware. Any paid upgrade goes into `docs/pitch/cost_model.md` first.
