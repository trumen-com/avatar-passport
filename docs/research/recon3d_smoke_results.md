# 3D reconstruction results

The 3D scope change is recorded in `docs/decisions/004-3d-reconstruction.md`. Candidates and licences are in
`recon3d_candidates.md`.

Tables between the markers are generated by `scripts/render_recon3d_results.py` from the run reports under
`outputs/recon3d/`. They are measured on the dev laptop (RTX 5050 Laptop GPU, Ryzen 7 260, 16 threads), and none is typed
by hand. The 2-thread runs are pinned to one physical core (`taskset -c 0,8`) as a proxy for the 2-vCPU Hugging Face
CPU Basic host. That proxy is an optimistic lower bound.

Input is only the anonymised frames: `data/processed/frames` (29 frames at 1 fps), or the 115 frames extracted at
4 fps and blurred before saving, for the high-quality path.

## Observations

1. **Speed.** DA3 runs on the CPU, so the 3D model can be built on the CPU-only deploy target. It is slow, but it works,
   which the user accepted for the demo (see the timings above).
2. **First user review.** The user judged the first point-cloud preview too blurry and distorted. Changes made in
   response:
   - higher processing resolution;
   - car-only masks from the parts model;
   - more points kept;
   - a z-buffer preview renderer.
3. **High-quality path.** For accuracy and detail, the user asked for more frames from the video and better calibration.
   That became this path: 4 fps frames, COLMAP calibration, then Gaussian splats. It needs a GPU.
