# ROI model for the after-sales unit (illustrative)

> **No partner data was available.** Royal Motors has not given us volumes, dispute counts, conversion rates, margins, wages or an accessory price list. Every input marked **ASSUMPTION** below is a placeholder to replace with partner data. Every ROI figure is **illustrative, not a forecast**. The price inputs are observed public "from" prices (lower bounds), not dealer prices.

- **How the numbers are made.** The tables between the `roi` markers are generated by `python scripts/roi_calc.py` from its parameters block, the observed price CSV and the measured timing files. Re-run it after any change; `--check` exits 1 if the tables are stale.
- **Changing an assumption.** Override it without editing code. Example: `python scripts/roi_calc.py --set dispute_rate=0.002,0.004,0.008 --print`.

## 1. Value drivers (per month)

N = inspections per month = `branches` x `inspections_per_branch_day` x `working_days_month`.

| driver | formula | what it means |
|---|---|---|
| disputes avoided | N x `dispute_rate` x `dispute_avoided_share` x `repair_ticket_uzs` x (1 - `gross_margin`) | Each dispute the dealer loses is assumed to cost one goodwill repair at the dealer's own cost (price minus margin). A timestamped, hashed passport settles a share of them. |
| repair upsell | N x `damage_found_share` x `repair_conversion` x `repair_ticket_uzs` x `gross_margin` | Damage found at intake that the customer then repairs at the dealer's body shop. Margin only, not revenue. |
| accessory upsell | N x `tryon_conversion` x `appearance_ticket_uzs` x `gross_margin` | Appearance sales attributed to the paint try-on. There is no accessory price list, so observed polishing prices are used as a proxy ticket. |
| advisor time | N x (`paper_walkaround_min` - `app_handling_min` - wait) / 60 hours, where wait = processing seconds / 60 x `advisor_wait_share` | Hours saved compared with a paper walkaround. They are converted to UZS only if `--advisor-cost-uzs-per-hour` is given; there is no wage data, so by default they are **not costed**. Processing time is the HF CPU Basic planning figure (2-thread pinned proxy x2, optimistic lower bound; `cost_model.md` section 3). |

**Cost side**
- Hosting = HF PRO $9/month + CPU Basic $0/hour (ADR 003), converted at 11,897.90 UZS/USD (CBU, 2026-10-10, `docs/research/market_prices.md` section 1).
- Team time, integration and training are **not costed** (`cost_model.md` section 6). The value/cost ratio is therefore against hosting only.
- Break-even = hosting per month / (`repair_ticket_uzs` x `gross_margin`): the number of upsold repairs per month that pay for hosting.

**Price inputs** (from `data/reference/repair_prices.csv`, `docs/research/market_prices.md` section 2):
- `repair_ticket_uzs` uses the per-part rows of the paint, dent, scratch and panel-replacement categories, the same rows `cost.estimator` uses.
  - low = the lowest per-category median;
  - base = the median of all those rows;
  - high = the highest per-category median.
  - Polishing rows are excluded because they are full-body detailing (market_prices.md section 2 caveats).
- `appearance_ticket_uzs` takes min / median / max of the three polishing rows, including an ended dealer promo. It is a **proxy**.
- All are "from" prices, so they are lower bounds. The three OLX rows are probably one business.

## 3. How to read it

- **Scenarios are joint.** "Low" puts every assumption at its pessimistic value at once, and "high" at its optimistic value at once. The high column compounds several optimistic guesses and is not a plausible single outcome. The one-way sensitivity table is the better guide to what matters.
- **What matters most.** In the one-way table, the largest swings come from volume (`branches`, `inspections_per_branch_day`) and from the repair-ticket price. Those are the first numbers to get from the partner.
- **Break-even.** With these inputs, fewer than two upsold "from"-priced repairs a month cover the $9 hosting in every scenario (break-even row). That claim depends only on the observed prices, the margin assumption and the PRO price. It ignores team time.
- **Advisor time can be negative.** In the low scenario the advisor waits for CPU processing, which takes minutes on the 2-thread proxy. A GPU worker or background processing removes that wait. The GPU options and their prices are in `cost_model.md` section 6.
- **Detection quality limits the upsell driver.** `damage_found_share` assumes the model finds real damage. On our only test car, which was undamaged, every detection was a **false positive** (`docs/research/smoke_test_results.md`, Observations 3). Recall has not been measured (Phase 2). False positives cost advisor time to dismiss, and this model does not count that cost.
- **Licences limit commercial use.** The damage weights are demo/research only (CarDD, non-commercial; ADR 001). A paid pilot needs a model retrained on licensed data, and that cost is not in this model.
