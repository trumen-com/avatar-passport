# CLAUDE.md — AvtoPassport (hackathon project brief for Claude Code)

Read this whole file before doing anything. It is the source of truth for scope, rules and structure.

## 1. What we are building

**AvtoPassport**: a phone walkaround video of a car becomes a verified **digital condition passport** tied to the car's VIN.

Mode: **Partner product** for Toyota Royal Motors / BYD Royal Motors, owned by the **after-sales unit** (service reception, body shop, accessories). Process changed: **vehicle intake / trade-in inspection** (today: manual paper walkaround → missed damage, "that scratch wasn't there" disputes, lost repair and accessory upsell).

Core user flow:
1. Advisor (or a jury member on their own phone) records a 30–60 s walkaround video + a close-up photo of the VIN plate/sticker.
2. In ~10–20 s the app returns a passport:
   - VIN card (make / model / year / plant, decoded).
   - 360° spin viewer built from the video frames, with damage pins.
   - Damage list by car part, with severity, recommended action (polish / paint / repair / replace) and cost in UZS from a local price table.
   - History for this VIN = previous AvtoPassport inspections, with a diff: "new damage since last inspection".
   - Paint try-on: the real car recoloured in 6–8 colours.
   - 3D model of the car reconstructed from the walkaround frames, with damage pins (built in the background after the passport is returned; slow inference is acceptable for the demo as long as it really runs — scope change 2026-10-11, see `docs/decisions/004-3d-reconstruction.md`).
   - Nearby body/paint shops (OpenStreetMap).
   - Shareable passport page + PDF with a SHA-256 hash of the source frames and a timestamp.

## 2. Hackathon rules that constrain the code (do not violate)

- **No faked demos**: no hard-coded answers, no mock screens presented as working, no invented metrics. Every number in the UI or deck must come from code that runs.
- **No real personal/confidential data**: no customer records, no faces or plates of non-consenting people. Plates and faces must be blurred in everything we store, show or commit.
- **Confidential-type data is synthetic and declared**: anything that in reality lives in police / insurer / dealer systems (owners, accidents, insurance claims, customer records) is generated by `scripts/generate_synthetic.py` with a fixed seed. Every synthetic record has `"synthetic": true`, and the UI shows a visible **SYNTHETIC DEMO DATA** badge on anything derived from it. It is presented as "registry connector — sandbox", never as real history. Synthetic records use synthetic VINs only; never attach synthetic history to a real scanned VIN.
- **Attribution**: every dataset, model and library goes in `DATA_SOURCES.md` with its licence. Check licences on model cards; flag research-only / non-commercial ones.
- Must be deployed publicly (web, works on mobile browsers), deployed from this repo. After the deadline only redeploys of the submitted commit are allowed.
- Must report: where inference runs, speed on our hardware, cost per inspection, and quality at night / rain / on local cars.

## 3. Build order (Colab first, then app)

Work in this order. Do not start the app before Phase 1 passes.

### Phase 0 — Research (write findings to `docs/research/`)
Verify current availability, licence and loading code for:
- Damage segmentation (pretrained, no training): candidates on Hugging Face, e.g. `mitbersh/car-damage-segmentation` (YOLO26-m-seg, 6 classes, `damage_segmentation.pt`, imgsz 896) and `Danishali273/Car-Damage-Type-Segmentation` (classes: crack, dent, glass shatter, lamp broken, scratch, tire flat). Search for others.
- Car-part segmentation: Roboflow Universe hosted models (API key, cost goes in cost model) **or** train a YOLO nano/small seg on Ultralytics' built-in `carparts-seg.yaml` (~3.8k images) on Colab GPU (~1 h). Prefer self-hosted if time allows.
- Generic detection for car / person: COCO-pretrained YOLO.
- Plate detection for blurring: an open-source plate detector, or SAM 3 with text prompt "license plate" as fallback (SAM 3 needs GPU; avoid on CPU deploy).
- VIN OCR: PaddleOCR vs EasyOCR. Add our own validation (17 chars, alphabet without I/O/Q, confusion fixes 0↔O, 1↔I, 8↔B, 5↔S; ISO 3779 check digit where applicable).
- VIN decoding: NHTSA vPIC API (`https://vpic.nhtsa.dot.gov/api/`) + our own WMI / model-year table in `data/reference/wmi_table.csv` for Chinese and Uzbek-built vehicles. Verify each WMI from a public source and cite it.
Write `docs/research/model_candidates.md` with: name, link, licence, classes, size, CPU latency, notes.

### Phase 1 — Colab smoke test (`notebooks/01_smoke_test_colab.ipynb`)
Must run top-to-bottom in Google Colab (GPU and CPU runtime):
- Install cell, GPU check, load inputs from `data/raw/` (upload or Google Drive mount).
- Extract frames from `data/raw/video/*` at 2–3 fps; quality filter (Laplacian blur variance, brightness).
- Run every candidate damage model + parts model on the frames and the photos in `data/raw/images/`; save annotated outputs to `outputs/` (gitignored).
- OCR on `data/raw/vin/*`, validate, decode.
- Print per-frame latency on CPU and GPU.
Pass condition: annotated images look sensible, VIN read correctly or failure understood, latencies recorded in `docs/research/smoke_test_results.md`.

### Phase 2 — Evaluation on our own test set (`notebooks/05_eval_local_testset.ipynb`)
- Team photographs 60–100 local cars (parking lots, no people in frame; blur plates). Label damage (polygons) and damaged part in Roboflow or CVAT; export COCO to `data/local_testset/`.
- Slices: `day`, `night`, `wet`, plus car brand.
- Metrics: mask mAP50 per model; **part-level recall** (was each damaged part flagged?); false positives per car (reflections, dirt); VIN OCR exact-match rate; latency per frame and per full inspection on the deploy CPU.
- Pick the best model per job and calibrate per-class confidence thresholds on this set. Report baseline vs calibrated.
- Save a failure-case gallery to `docs/assets/failure_cases/`.
- All numbers go to `docs/research/evaluation.md`. These are the deck numbers.

### Phase 3 — Pipeline package (`src/avtopassport/`)
Pure Python, testable, no UI code. Port working notebook code here; notebooks then import from `src/`.

### Phase 4 — App + deploy
- Backend: FastAPI (`src/avtopassport/api/`), models exported to ONNX, CPU inference.
- Frontend: mobile-first static page in `web/` served by the same FastAPI app (one deploy). Camera/video capture via `<input type="file" accept="video/*" capture="environment">`, upload progress, spin viewer, try-on, passport page, 3D viewer (async job; shows "building…" until the model is ready).
- Storage: SQLite for passports (VIN → inspections). Images stored only after blurring.
- Deploy: Dockerfile → Hugging Face Spaces (Docker) or Render. GitHub Actions workflow in `.github/workflows/deploy.yml`.
- Test on at least 3 different phones. Record a backup demo video.

## 4. Pipeline design (`src/avtopassport/`)

```
video/images ─► frames.extract ─► quality.filter ─► privacy.blur (plates, faces)
                                                       │
                       ┌───────────────────────────────┤
                       ▼                               ▼
                 damage.segment                  parts.segment
                       └──────────► mapping.assign (damage mask ∩ part mask → part)
                                         ▼
                                  dedupe.merge (same part + type across frames)
                                         ▼
                                  severity.rate (damage area / part area, type → action)
                                         ▼
                                  cost.estimate (data/reference/repair_prices.csv)
VIN photo ─► vin.ocr ─► vin.validate ─► vin.decode
                                         ▼
                 passport.store (SQLite, by VIN) ─► passport.diff (vs previous inspection)
                                         ▼
                 passport.report (JSON + PDF + SHA-256 of frames) ─► api ─► web
tryon.recolor: body-panel mask (parts minus glass/tyres/lights) → LAB hue/chroma shift, keep L channel
recon3d.build (async): blurred frames → 3D model + camera poses → damage masks projected to 3D pins → web 3D viewer
```

Rules: each step a pure function with typed inputs/outputs; log timing per step; never let one failed frame crash the run; return a structured "could not read VIN" instead of guessing.

## 5. Data policy

| Data | Real or synthetic | Where |
|---|---|---|
| Team's own car video/photos/VIN | Real, consented, plates & faces blurred before commit | `data/raw/` (raw gitignored; blurred copies in `data/processed/`) |
| Local test set | Real, team-collected, blurred | `data/local_testset/` |
| Repair prices | Real, collected by phone from Tashkent body shops (source + date per row); if a price is our estimate, mark `is_estimate=true` | `data/reference/repair_prices.csv` |
| WMI / VIN decode table | Real public info, cited | `data/reference/wmi_table.csv` |
| Registry history (owners, accidents, insurance claims), dealer customer records | **Synthetic**, seeded, flagged | `data/synthetic/` via `scripts/generate_synthetic.py` |

Synthetic generator requirements: fixed seed; synthetic VINs with valid format and check digit, prefixed in metadata as synthetic; realistic distributions documented in `data/synthetic/README.md` (method + assumptions); no real names — use obviously synthetic names or IDs.

## 7. Out of scope (do not build; roadmap slide only)

- ~~Real 3D reconstruction~~ — moved IN scope on 2026-10-11 (user decision): built asynchronously, slow is acceptable for the demo, must really run; reconstructed only from blurred frames. The spin viewer stays as the fast view and the fallback.
- 3D rims / body kits / spoilers. Optional only if time remains: a clearly labelled "AI preview" via an image-editing model API, cost included.
- Real police / insurer registry access.
- Police as a user.

## 8. Definition of done

- [ ] Colab smoke test runs end to end on our video, photos, VIN image.
- [ ] Evaluation numbers on our local test set, with day/night/wet slices and failure cases.
- [ ] Public URL works on 3 phones; full inspection time measured on deploy hardware.
- [ ] Repeat inspection of the same VIN shows a correct "new since last inspection" diff.
- [ ] Synthetic data badge visible wherever synthetic data appears.
- [ ] README, DATA_SOURCES.md complete; no raw plates/faces in the repo.
- [ ] `docs/pitch/` has cost per inspection, pilot budget and ROI with every assumption stated.

## 9. Working style

- Ask before adding a paid API. Every paid call goes into `docs/pitch/cost_model.md`.
- Prefer the smallest model that meets quality; measure, don't assume.
- Write findings into `docs/` as you go — they become the deck.
- Commit small and often; the deployed commit must match the submitted repo.
